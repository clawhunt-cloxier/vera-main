# 跨 Agent 与人类协作

Codex 与 Claude Code 是可互换的实现者/审查者，不以模型名称决定永久模块所有权。主维护者为仓库所有者；每个任务仅一位当前负责人。

每次会话先从dev拉取已合入状态，检查TASKS的依赖和工作范围。任务领取/发布按CONTRIBUTING；不同worktree避免共享未提交文件。公共contracts和迁移序号必须串行分配，界面与独立算法可在已冻结契约下并行。

## 交接格式

`docs/handoffs/YYYY-MM-DD-<task>-<actor>.md`：任务/owner/分支/基线commit、目标、实际完成、文件、执行命令及结果、未完成、阻塞、下一步、风险。时间用UTC。Git提交是代码事实，handoff只解释上下文。

超过一个会话的工作需小提交，更新任务与交接；不得以“已写代码”代替通过测试。遇到外部密钥缺失时完成可独立验证部分，将任务标BLOCKED并注明依赖，不伪造实现。

## 建议分工

第一位实现T002数据/基础设施，另一位在T002契约稳定后实现T003身份与T007前端准备。T004治理与T005 Agent按契约顺序集成。代码审查使用docs/reviews模板，审查记录须明确实际查看commit，不能冒充另一Agent已审查。

不需要两位Agent同时在线，也不需要共享聊天。冲突由规范、任务状态和Git记录解决；研究结果的全自动流程与工程审查完全分离。

任务 PR → dev → 发布 PR → main；详见 [分支规范](BRANCHING.md)。
