# 网站页面规格（MVP）

状态：MVP 规格。目标是让功能完整、信息清楚；视觉效果后续迭代，可替换样式而不改数据流。接口与字段以 [contracts/openapi.json](../contracts/openapi.json) 为准。

## 1. 技术约定

- React 19 + TypeScript + Vite；TanStack Router（文件路由）与 TanStack Query；ECharts 用于图表。
- API 类型由 OpenAPI 生成（T011），组件不得手写与契约重复的类型。
- 所有写请求带 CSRF token；创建计划确认、反馈、自选股添加带 Idempotency-Key（前端生成 UUID）。
- 只有中文界面；时间按 Asia/Shanghai 显示，接口传输仍为 RFC3339。
- 金额、比例由前端按 display 规则格式化显示；报告中的数值直接使用接口返回的展示字符串，不在前端重新计算。
- 桌面宽度 ≥ 1024px 为主；手机 ≥ 360px 可用：侧栏改为底部抽屉，表格横向滚动。
- 可访问性基线：语义化标签、键盘可操作、焦点可见、颜色对比度满足 WCAG AA、状态不只用颜色表达。

## 2. 路由

| 路由 | 页面 | 登录 |

## 3. 页面要点

### 3.1 workspace 首页

- 顶部一句话输入框（≤500 字）。下方展示当前可用研究类型的示例，点击填入输入框。提交后调用 `POST /research-plans`。
- 输入框下方显示研究技能卡片，点击后进入“技能 + 搜索对象”的结构化输入（实体搜索为下拉自动完成）。
- 工作台只提供个股分析、资金动向和深度研究三个研究入口；仅提供个股行情分析的部署使用同一个个股分析入口。快速启动按当前技能的 `subject_kinds` 筛选研究对象，仅在该版本的 `params_schema` 允许时提供“公司 + 所在行业对比”。旧行情快捷入口回到个股分析，不影响历史计划或报告。
- 用户选择研究类型和对象，网页自动协商取数能力。支持收盘研究与行情发现的部署，三个研究入口均可按简称或代码查找 A 股；主操作准备资料后以普通 JSON 创建所选研究类型的固定截止计划。仅通过行情目录发现的个股也可单独选择较短的成交简报。仅有行情的部署继续使用其可用协议。证据和报告按实际来源列明日期、口径和覆盖限制。
- 初次准备可能耗时数分钟；等待提示描述用户正在请求的研究，切换证券或离开页面停止该次页面轮询。暂时限频时自动重试；数据、权限或章节不足时说明具体影响。
- 自由描述沿用 Harness 的意图解析及已有实体目录。首次查找目录外的股票时，可在三个技能的“研究对象”中输入证券简称或代码。
- 桌面左侧放置输入框、快速启动和最近任务，右侧工作助手提供历史报告入口和自选股摘要。自选股显示前 10 只和已有提醒。窄屏按阅读顺序排列为单列。
- 工作区与报告阅读器使用 Vera 头像和字标。账户菜单支持键盘展开、收起，按 Escape 后回到触发按钮。
- 配额剩余显示在页头。

### 3.2 计划确认

`PlanResult.kind`：

- `plan`：显示技能、对象、参数（可调整的参数用下拉，如资金动向窗口）、章节列表（必需章节锁定，可选章节可取消，unavailable 章节灰显并显示原因）、预计耗时、配额消耗。按钮“开始研究”。
- `collect_latest` 显示计划预览时间和最近可用行情策略，说明确认后采集、再冻结一次快照；行情缺失、过期或无法核验时按技能规则弃权或标记限制。读取旧计划时保持其固定截止时间或历史行情语义，确认使用该计划的原协议版本。
- 固定截止计划始终用普通 JSON 提交任务。即使刷新确认页后读到 `quote_requirement=latest_available`，也沿用创建时的协议。仅对 `collect_latest` 计划按该字段区分 0.4 和 observation.v1。
- `choose`：列出候选（技能 × 对象），点击后重新请求计划。
- `unsupported`：显示原因和 `suggestions` 中的替代研究。

计划过期（409）时提示并自动重新生成。

### 3.3 任务进度

- 显示对象、研究类型、创建时间。运行中统一显示转圈及等待文字；取消请求单独确认。运维可通过既有接口读取步骤和内部状态。
- 轮询间隔取 `Retry-After`，终态停止。
- 对采集后冻结的任务，`snapshot_as_of=null` 时显示快照尚未冻结，冻结后显示真实截止时间，不以预览时间代替。
- 可取消；取消后显示“取消处理中 / 已取消”。
- 已完成任务链接到已交付的报告。未交付、额度用尽、主动取消、暂时无法执行和失败分别显示结果及可用原因，重新研究入口回到相应研究类型。提示保留数据与授权限制，接口错误带请求编号。

### 3.4 报告阅读

- 抬头：标题、对象、技能、数据截止、版本、full/limited 标签、“AI 生成”标签。
- ADR-0004：采集后冻结的报告显示快照截止时间；按 `source_freshness` 分别展示事件、披露、接收、可用时间、数据期间、新鲜度、延迟性质和来源限制。证据侧栏显示相应字段，时间精确到秒并使用北京时间。实时传输标签不推断交易状态，盘后、休市或停牌说明保留在来源限制中；旧报告仍按原字段展示。
- 桌面用窄目录导航，报告标题和结论使用宋体字形，导航和表格使用无衬线字形。长段落限制行宽，表格和图表使用正文列的可用宽度，图表随证据栏开关调整。手机章节目录从工具栏下方展开，宽表可在表内左右滚动。
- 至少 1100px 宽时，正文与证据并排阅读。较窄的窗口从底部展开证据，关闭后回到所选引用。章节锚点在固定目录下方可见。
- 账户菜单、证券搜索列表、手机目录和证据面板分别按控件大小设置过渡。桌面研报逐步为证据栏腾出空间，手机抽屉覆盖正文。开启系统减少动态效果时立即展开和收起。
- 下载入口在研报顶部的固定工具栏，用下载图标和“PDF”标识。打开或关闭证据栏时，下载入口的位置保持稳定。
- 图表标明单位、图例和来源图注。同一交易日或报告期对齐，缺失点保留空档，柱状图以零为基线。接近视口时绘制并按当前列宽更新，离开视口后保留图例选择。浏览器打印时绘制所有已读取的图表。
- 导出 PDF 使用 A4 排版和内嵌思源黑体。目录续页重复目录标题，长表续页重复列头。正文续页显示页码和数据截止。图注和图表同页。
- 普通 `1.0.4` 报告的 A 股补充日成交表在网页和 PDF 中按厂商日期展示，成交量用手（100 股），成交额用万元（10,000 元），换手率用百分比。成交量额至少显示两位小数，保留更多有效小数和缺值。股价继续按每股报价，结论原文、归档值及计算口径保持原样。证据显示独立来源、接收时间和报表换算口径。历史 Choice observation 简报沿用手、万元与两位小数。公告与新闻可展示页码、公告编号或出处，归档指纹、字段索引与内部比例用于溯源。
- 每条结论末尾显示引用编号 `[n]` 和结论类型的小标签（事实/计算/推断/引述/情景）。点击 `[n]` 打开右侧证据侧栏：值、单位、口径、来源等级、厂商、时点、原文片段或计算公式与输入。
- 区间计算的来源按每页 12 条读取，可逐页查看全部来源。
- 情景结论单独以卡片显示：触发条件、观察指标、失效条件。
- 末尾：数据与限制、来源列表、免责声明。
- 操作：加入自选股、对结论反馈（点击结论旁的反馈按钮选择类型与备注）、用同一对象发起其他技能研究。
- 不展示被删除的结论和模型原始输出。

### 3.5 自选股

表格列见 [watchlist](skills/watchlist.md) §1；支持标签筛选、排序、编辑提醒（弹窗）、一键生成研究计划。触发提醒的行在首列显示提醒标记，悬停显示触发事实。

## 4. 状态与错误

每个数据区块都要有加载、空、错误三种状态。错误显示 `error.message` 与 `request_id`；401 跳转登录；429 显示配额说明。

## 5. 测试

Playwright 覆盖：登录 → 首页一句话 → 计划确认 → 进度 → 报告 → 打开证据 → 反馈 → 加入自选股 → 自选股列表；以及 unsupported、choose、ABSTAINED 三个分支；桌面与 390×844 手机视口各跑一次。测试使用 fixture 数据和录制回放的模型响应。

0.4 前端验证：`make test-web-client`（已纳入 `make verify` / CI）检查请求/响应媒体类型、降级拒绝以及旧计划的原协议确认。先执行 `cd web && npm ci && npx playwright install --with-deps chromium` 安装浏览器及系统依赖，再运行 `npm run test:realtime-ui`；该测试使用明确标注的模拟 API 数据，在桌面和手机视口验证最近可用行情默认策略、计划确认、冻结截止与证据时间展示，并检查旧 observation 与历史报告兼容。这不替代真实厂商端到端验收。
