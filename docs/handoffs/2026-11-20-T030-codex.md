## 交付与复验

开发已提交到 PR #40，目标分支为 dev。实现与运维说明见 [TuShare 收盘研究](../TUSHARE.md)。以 `3fa88c9` 为接口、归档和服务装配基线，`08acdbb` 接入网页三技能，`40f2c37` 与 `17a66b2` 隔离历史报告、自选指标和命令回放，`63859d1` 支持测试部署后台采集。工作树之外的主检出保留原状。

- 在 Linux 上运行 `make verify`，通过文档、公共契约、Go 竞态测试、前端协议、静态检查和构建。Go 包测试需可启动 PostgreSQL，公告提取需 Poppler 和 util-linux。
- `cd backend && go test -race ./internal/app -run '^TestTuShareThreeReportDelivery$' -count=1 -v` 使用合成 TuShare HTTP 响应、可提取的中文 PDF、PostgreSQL、S3 协议测试存储与模拟模型。首次发布 10,780 条记录，重复同步新增 0。工作台 API 和 worker 生成个股 full（50 条结论、4 张图）、资金 limited（25 条、3 张图）、公司深研 limited（58 条、1 张图）。实际读取证据、计算输入与序列，渲染三份 PDF，共 20 页。撤销模型用途后相关证据、计算和 PDF 均返回 503。
- `cd web && npm run test:realtime-ui` 的 Chromium 用例检查三项快速入口、计划确认、报告、证据和 PDF 链接，网页使用模拟 API。PDF 导出已分别渲染为页面图像检查分页、图表和中文显示。
- 尚需在测试环境注入账号 Token，检查实际订阅、公告原文可访问性、真实模型报告并核对引用。开发机到官方 API 的无凭证 TLS 握手出现 EOF，部署时应先从运行容器执行名录探测。真实 V02 验收仍开放。
