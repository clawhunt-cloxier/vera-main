# T017 交接：模型网关补齐（Claude-Code，2026-11-13）

分支 `agent/claude/T017-model-gateway`，基于 origin/dev（c301eba）。本 PR 不含迁移。

## 已做

- **按 profile 配置**（`MODEL_<PROFILE>_*`）：`THINKING`（enabled/disabled，未设置时不发送，沿用厂商默认）、`TEMPERATURE`、`MAX_OUTPUT_TOKENS`、`TIMEOUT_SECONDS`、`CONCURRENCY`、`EXTRA_BODY`。取值不合法时启动报错，不会静默回落到默认值。`EXTRA_BODY` 不能设置网关控制的字段（model、messages、max_tokens 等），网关也会在最后写入这些字段。
- **thinking 写入请求**：`{"thinking":{"type":...}}`。`EXTRA_BODY` 中显式写的 `thinking` 优先。
- **请求哈希**加入 thinking、temperature 与 extra body，不同配置不会复用同一份录制或成功调用。
- **输出上限**：取 profile 上限和调用请求值中较小的一个，预留费用也按它计算。
- **录制模式** `record`：命中录制时直接回放、不收费；缺失时转发真实厂商并落盘，只录制 `finish_reason=stop` 且内容非空的响应，写入时先写临时文件再改名。需要真实凭证和价格表，production 拒绝。
- **UNKNOWN 自动释放**：River 定时作业 `model.release_unknown` 每小时运行一次，把发送超过 24 小时仍为 UNKNOWN 的调用改为 RECONCILED，费用记 0，并在 error 字段注明。已接入 `vera worker` 和 `vera demo`。
- **测试** `internal/harness/model/failures_test.go`：429 遵守 Retry-After、4xx 不重试、超时记为 UNKNOWN 并保留预留费用以及 24 小时释放、空 content 与截断按格式错误处理且按实际 usage 计费、请求体字段与输出上限、高峰与非高峰计价、record 只对未命中计费且不录制截断响应。另有 config 测试覆盖各开关和非法取值。
