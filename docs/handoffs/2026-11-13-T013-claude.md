# T013 交接：身份差距补齐（Claude-Code，2026-11-13）

分支 `agent/claude/T013-identity-gaps`，基于 origin/dev（c301eba）。

## 已做

- **CSRF 只存哈希**（DATA_MODEL `sessions.csrf_hash`）：CSRF token 改为由会话 cookie 派生，`CSRFToken(session) = base64url(HMAC-SHA256(session, "vera-csrf-v1"))`。数据库只存它的 SHA-256，`/me` 仍能返回 token。校验用常数时间比较。
- **迁移 00005_session_csrf_hash**：新增 `csrf_hash`，删除明文 `csrf_token`。已有会话无法转换，迁移会将其吊销，用户需重新登录。Down 迁移同样吊销已有会话。
- **新增测试** `internal/identity/flows_test.go`：
  - nonce 不匹配时回调返回 400 `AUTH_NONCE_MISMATCH`，且不建会话；
  - PKCE challenge 被篡改时换码失败（`AUTH_EXCHANGE_FAILED`），且不建会话；
  - 数据库只存 CSRF 哈希，错误 token 返回 403，另一会话的 token 不可用，会话过期后返回 401；
  - 过期或已吊销的邀请码返回 400，不建 workspace，也不扣减次数。
- **V01 跨 workspace 隔离**（`internal/httpapi/api_test.go`）：在原有的报告、PDF、任务、证据、自选股删除之外，补充计划、计算记录、图表序列、反馈、取消任务、自选股 PATCH 均返回 404；三个列表接口不泄漏他人数据；另一 workspace 重放同一 Idempotency-Key 时拿不到原任务。
- **Keycloak realm** `deploy/keycloak/realm-vera.json`：机密客户端 `vera-web`、仅授权码流程、PKCE S256、密码策略、防暴力破解。密钥和回调地址用 `${VERA_OIDC_CLIENT_SECRET}`、`${VERA_PUBLIC_URL}` 占位，依赖 Keycloak 导入时的环境变量替换。**尚未在真实 Keycloak 上导入验证**，因为本地 Docker 未运行，Compose 属于 T012。
