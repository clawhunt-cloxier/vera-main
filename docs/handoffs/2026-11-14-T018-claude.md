# T018 交接：Harness 核心补齐（Claude-Code，2026-11-14）

分支 `agent/claude/T018-harness`，基于 T016 分支（#23）。并发测试依赖 #23 修复的事实表重载问题。含迁移 00006。

## 已做

- **步骤租约**（HARNESS §10.2，DATA_MODEL 已定义 `attempt`、`lease_until`；迁移 `00006_step_leases`）：
  - **领取**：条件 upsert，只能领取 PENDING/FAILED/SKIPPED 状态的步骤，或租约已过期的 RUNNING 步骤；领取时 `attempt+1` 并写入 `lease_until`。
  - **续租**：执行期间每 30 秒续租一次，租约默认 2 分钟。
  - **步骤忙**：步骤被另一个存活的 Worker 持有时，本次运行返回 `ErrStepBusy`。River 作业对此延后重试，不消耗重试次数；章节并行时也不会把可选章节误判为省略。
  - **防护令牌**：只有 `attempt` 仍匹配时才写入结果。租约被接管的 Worker 恢复后不能覆盖结果，改用接管者已保存的结果。
- **核心要点语义核验**：新增 `verify:summary` 步骤。逐字引用单条结论的要点不再核验，改写过的要点由核验器逐条判断，只保留 supported。核验不可用或保留不足 3 条时，改用确定性摘要（逐字引用已核验结论）。新增提示词 `summaryVerifyRules`，`PromptVersion` 提升到 1.1.0。
- **测试**：
  - `lease_test.go`：并发 Worker 互斥、租约过期接管与防护；V05：3 个 Worker 并发运行同一任务，只交付一份报告，没有重复的结论，也没有步骤产生两次成功的模型调用。
  - `summary_test.go`：被核验器否决的要点不会交付；保留不足 3 条时使用确定性摘要。
  - `deadline_test.go`：截止时必需章节已完成，则按 limited 交付，未完成的可选章节标注为省略。这项行为原本已存在，此前没有测试。

## 结论：原差距清单中的两项

- “截止或预算耗尽时必需章节已完成也不按 limited 交付”：实测可以按 limited 交付，已用测试固定。预算耗尽时只有可选章节失败的路径与此相同。
- “重复交付撞唯一键”：交付在一个事务里锁住任务行并校验状态，并发运行时第二个交付会被判为过期，不会写入。V05 测试已覆盖。
