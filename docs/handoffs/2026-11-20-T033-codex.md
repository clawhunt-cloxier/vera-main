## 实现

- 工作台、快速启动和自选股只显示个股分析、资金动向和深度研究，不再显示数据源与“行情要求”选择。新版计划使用普通 JSON，由服务端写入唯一行情口径 `latest_available`；历史简报仍按原协议读取和确认。
- 三项 `1.0.4` 技能以 TuShare 登记的收盘与披露数据为主，Choice 已归档的日成交量、成交额、换手率作为独立补充。通用补充来源注册接口不把多个厂商的取值拼成一条标准日线；任务按工作区、epoch、冻结快照和归档哈希绑定，每次模型使用与报告读取均重新检查当前权限。
- 个股有证券身份、行业分类、相对表现及成交证据；资金动向有行情、融资覆盖和在有源数据时的龙虎榜；深度研究单列市场表现并保留公司和行业证据门槛。可核验的可选章节表格不因模型缺少文字输出而消失。报告列表可保留不含行情或结论的任务元数据；报告正文、PDF、图表和引用的补充证据不可在绑定来源失效后继续读取。
- 生产只读取已登记的数据，不能用虚构数据补齐缺项。TuShare `anns_d` 返回 40203 的情况下，财报、分部、年报经营和风险文本对应章节仍须披露不可用原因。Choice 日成交不是实时行情。

## 验证与发布

- 真 PostgreSQL 的公告无权限路由测试覆盖三类普通 JSON 计划与交付，验证服务端写入最近可用行情、缺失章节说明、计算溯源和 PDF 输出。数据服务的 Choice 补充测试覆盖归档请求、重放及权限撤销。样例是测试夹具，不是真实账号验收。
- 浏览器回归 11/11，API 客户端回归 4/4，包含不显示或提交行情要求、旧链接跳转、自选股和历史兼容。
- CI、dev 合并、测试站部署、真实多来源报告验收及文件导出须分别按实际结果确认。不得以历史简报或模拟报告替代这三项研究的现场验收。
