# T024 交接：管理 CLI（Claude-Code，2026-11-14）

分支 `agent/claude/T024-admin`，基于 origin/dev（c301eba）。本 PR 不含迁移。

## 已做

- **全部命令写审计**：所有命令统一经 `adminTo` 记录审计事件，包括只读命令和失败的命令（`result=failure` 并附错误）。审计写入失败时命令报错。邀请码明文不进审计。
- **`user reset-password`**：Keycloak Admin API 尚不可用，命令明确返回“未实现”（`errNotImplemented`），并记一条失败审计，不假装成功。
- **`user disable/enable`**：校验 ID，用户不存在时报错；停用与吊销会话在同一事务内完成。
- **`provider test <id>`**：只读请求当前提供方的实体与能力清单，报告数量与耗时，不写库。
- **`data sync --dataset --since`**：参数真正生效。按数据集与可用时点过滤记录（`dataservice.FilterRecords`）；Store.Sync 只新增，所以过滤不会删除其他数据。未登记的数据集报错。
- **`usage report`**：按用户与技能汇总；用 `--tz`（默认 UTC）计算自然日边界，修复了原先 `$1::date` 依赖数据库会话时区的问题。未结算或计价失败的调用按预留金额计，与网关预算一致。输出合计行。
- **`usage reconcile --release --cost`**：费用必须是非负金额；也可补记被 T017 自动释放的调用。手工核销过的调用不能再次核销。
- **`quota set`**：与已有覆盖合并，原先是整体替换；至少需要指定一项。
- **`vera harness replay --task <id> --dry-run`**：等同 `task inspect`，只读，不建评测 workspace、不调用模型。
- **测试** `cmd/vera/admin_test.go`：审计（成功、失败、只读、邀请码不入审计）、用户停用与会话吊销、reset-password 未实现、配额合并、数据同步过滤与审计、provider test、按用户与时区的用量报告、reconcile 校验、inspect 不存在的任务。
- **规范**：CLI 名称统一为子命令形式 `vera admin` / `vera harness`（规划冲突第 1 条），更新 OPERATIONS §4、ARCHITECTURE、HARNESS §11、CONVENTIONS。
