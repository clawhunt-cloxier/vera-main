## 背景

Codex 的 T014b 实现了真实厂商适配器（EMQuant），在其分支上重写了 `backend/internal/dataservice/store.go`。
我的 T014 在同一文件上加了血缘字段和 quality_state 过滤。两个分支都改 store.go，无文本冲突，但逻辑互补，需要手动合并保留双方所有改动。

## 合并策略

以 Codex 的 store.go 为基线（更完整：visibleAtCutoff、Freeze 事务重写、snapshot hash v2、synthetic 排除），把我的 lineage/quality 改动叠加在上面。

### 保留的 T014b 内容

- `excludeSynthetic` 字段 + `NewVendorStore()` 构造器
- `visibleAtCutoff` / `realSourceFilter` SQL 常量：
  - fin.statement/fin.segment 必须有 published_at 且不晚于 cutoff
  - vendor 记录不能挂到 synthetic 实体
- Freeze 事务重写：`snapshotDigest` v2（domain 前缀 `vera.snapshot.v2\x00`、RFC3339Nano、微秒截断）、legacy hash 保留、`FOR SHARE` 锁定、冲突检测
- 严格 provider upsert：kind/synthetic 冲突直接失败；`allow_model_processing` 用 AND 防止 sync 重新授予已撤销的权限
- 严格 entity upsert：synthetic 标记必须与现有行一致
- immutable record 冲突检测（CopyFrom temp table 比较 `ROW(...) IS DISTINCT FROM`）
- Snapshot 重查：manifest hash 校验 + 按 cutoff/权限 重新过滤存储的 ID
- 实体查询（Entities/EntityByCode/EntitiesByKind/Search/Mentioned）和 Get/Coverage/HasGlobal 全部加 synthetic 排除

### 保留的 T014 内容

- 血缘字段：`QualityState`/`RawRef`/`RawSHA256`/`RawLocator`/`MappingVersion` 在 `StoredRecord`、`recordCols`、Sync cols 数组
- `quality_state IN ('PASS','WARN')` 过滤在 Query / Coverage / HasGlobal / Snapshot / Freeze
- Freeze 的 quality 预检在事务开头跑（先查 badCount），通过后才做 temporal eligibility 的 FOR SHARE 查询
- 迁移 `00009_records_lineage.sql`（records 表加 raw_ref/raw_sha256/raw_locator/mapping_version/quality_state/revision_of）
- mapping loader + ApplyMapping + integer transform 防截断
- production guard（`GuardProduction`）

### 冲突协调点

- **mapping_version 类型**: 我用 `int`（迁移里 `int`），Codex 无此字段，无类型冲突
- **原始请求指纹**: 用 `raw_ref`/`raw_sha256`/`raw_locator` 三列，对应迁移 00009
- **WHERE 叠加**: Codex 的 visibleAtCutoff/realSourceFilter 替换了原来的简单 WHERE；我把 `AND r.quality_state IN ('PASS','WARN')` 作为独立 WHERE 条件叠加在后面（参数编号不变，因为 quality 不引入新参数）
- **Freeze**: Codex 的事务重写 + 我的 quality 预检共存——预检在事务开头
