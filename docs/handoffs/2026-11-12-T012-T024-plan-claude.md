## 2. 需要决策或修文档的冲突

1. 二进制名：规范写 `vera-admin`、`vera-harness`，代码为 `vera admin`、`vera harness`。拟修文档为子命令形式。
2. DATA_MODEL 的 `records_*` 按数据集分表与 MVP 单一 `records` 表；`calculation_runs`/`fact_sheets` 共享区与 MVP 每任务私有 `calculations`。拟以 ADR 记录 MVP 形态并补齐血缘字段，而非拆表。
3. `sessions.csrf_hash` 与 `/me` 返回 `csrf_token`：改为服务端只存 HMAC 摘要、令牌由会话密钥派生。
4. 公式 ID 与事实 ID 同用 `F##` 前缀；F19 未定义；F26–F28 只在代码中；DATA_SERVICE §3 的 28 个数据集与 catalog.json 的 23 个不一致。
5. DELIVERING 是否为持久状态；截止后组装的时间余量；R-09 的“章节字数”口径；每章最少结论数。
6. 花费以 `usage_ledger` 还是 `model_calls` 为准；UNKNOWN 自动释放后账单出现收费如何处理；RECONCILED 状态未入规范。
7. T023 目标形态（Caddy、Keycloak、多容器）与当前测试环境（host nginx、单容器、开发登录）不一致；DEPLOYMENT 描述的是 MVP 形态。
8. 自选股快照的“收盘数据可用后”无触发定义；SA-06/DR-03 的 ABSTAINED 运行时用例缺失；对抗样本注入机制未定义。
