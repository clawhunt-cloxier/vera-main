# ADR-0006：工作台对话流研究

状态：T044 实施，T045 更新对话工具与回复协议。

## 产品流程

- 认证工作台增加对话输入和私人历史。发送消息即开始处理。需要时请用户澄清标的或时间窗口，范围确定后由服务在后台建立计划并自动执行。首页保留正式研报、自选股及历史任务入口。
- 首批支持 A 股单证券的日成交与融资余额。每轮短研究展示已核验结论、数据表、图表、口径、实际覆盖、数据截止和证据。只开放部署当前已登记的数据和技能。需要其它完整研究时，使用现有研报计划与报告入口。
- 新问题可继承上一轮已执行的研究范围。明确的新标的、窗口或主题更新范围。解释、来源和公式使用指定轮次的交付版本。明确的新取数、计算和完整研报请求自动执行。独立研报入口保持原有计划确认流程。
- 沿用 [ADR-0003](0003-product-harness-runtime.md) 的 D2 输出边界、D8 计划确认（独立研报入口）及 [Harness](../HARNESS.md) 的确定性约束。已核验后一次性交付研究正文。任务进度使用可恢复的轮询。产品配额和用量展示延至商业化阶段，后台保留调度与模型运行门限。

## 接入方案

会话由 Go 服务管理，React 通过同源 JSON 接口发送消息与动作。PostgreSQL 保存会话、轮次、最近研究范围及计划或任务引用。工作区由认证上下文确定，私有表使用 RLS 和复合外键。业务命令用唯一键和轮次版本处理重试。计划、轮次和任务绑定使用事务，River 任务状态是终态及可用报告的依据。

Harness 为短研究登记版本，按主题限定数据、窗口、计算、章节和预算。单 Choice 日成交使用独立版本并复用成交观察的归档与核验。会话通过报告 ID 和版本重新读取结果、图表和证据，沿用当前来源授权。历史列表保存会话信息与引用。会话默认保留 90 天。删除会话时在同一事务取消在途任务，交付时检查会话仍有效。后台清理会话专有数据，已交付的完整研报按原留存规则管理。

在上下文装配处保留 RAG 摘要、上下文引用和偏好装配的接入位置。它们受 workspace 隔离、来源用途、删除和保留期约束。专家及量化研究随 Harness 的技能版本登记扩充，取数和计算由受信代码执行。会话命令接收受信 principal 与渠道身份，未来 IM 可经显式账号绑定、外部消息去重和用户确认使用相同服务。首版接入网页。

对话 Agent 使用网关的 `router` 配置理解每条消息。模型调用已声明的工具发起研究、调整范围或引用历史交付。服务匹配原文标的与登记别名，校验交易日窗口和技能可用性，按会话权限执行。标的未登记或有歧义时，用户可补充名称或使用证券目录。用户点选的历史结果拥有最高上下文优先级。工具及其窗口和对象限制见 [对话工具契约 v9](../skills/conversation-research.md)。

工作台发送消息时设置 `automatic=true`，服务在范围明确后自动执行。旧版接口客户端可以省略该字段，仍可生成计划后调用已有的确认动作。不含研究的旧版会话消息可在旧客户端原有的消息栏阅读。

模型通过 `respond_to_user` 写出回复类型和正文。网关使用 OpenAI 兼容的 Chat Completions，接受用同一 Schema 返回的 JSON。回复模型按金融教育和投资建议的语义边界生成正文。服务检查文本格式，然后发起语义审核。审核结合最后一问和已交付的问答识别通用机制和具体行动建议。核验只能保留或丢弃原稿。以后可在该审核入口接入专用内容分类器。会话状态仍由 PostgreSQL 管理。具体标的事实及数字进入报告和证据核验流程。混合请求可以完成可独立核验的历史研究，同时展示本轮交付范围。外部服务的业务性质与资质评估见 [发布规范](../RELEASE.md#financial-compliance)。

首条消息触发独立的标题作业。模型只收到该消息，标题校验后写入工作区历史。生成失败时保留通用标题，问答和研究各自执行。标题和消息按同一会话保留期清理。

这项决定更新 ADR-0003 D3 的模型职责。对话模型可以选择应用声明的工具并提出参数。Harness 写作与核验阶段接收冻结事实，取数、公式和最终交付由 Go 服务执行。对话中的一次 Tool Call 可在后台启动任务，工作台接收状态、数据和证据，后续引用使用已交付版本。

对话按现有技能调用财务、资金与行业场景的研究流程。多个专家共同研讨、量化计算、RAG 摘要、用户偏好与 IM 适配仍按各自的数据与评测要求演进。未来接入点分别是 Harness 技能版本登记、会话上下文装配与身份认证后的会话命令。

## 实施计划

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1. 冻结接口和数据模型 | 会话、轮次、计划绑定、结果投影、数据留存和权限契约 | 增量迁移可重放，OpenAPI 校验及生成类型通过。 |
| 2. 接通 Harness | 日成交、融资余额、短报告、自动入队、幂等重试和取消 | 实际任务和快照交付，覆盖缺数据、禁用表达及可回溯的数值与序列。 |
| 3. 接通工作台 | 新会话、历史、多轮追问、标的澄清、金融问答和报告证据 | 桌面与手机端从首页完成查询、刷新、续问、核对证据及转完整研报。 |
| 4. 验收与交接 | PostgreSQL、River、浏览器、原研究协议和 PDF 回归 | 验证隔离、重复提交、撤销权限、任务恢复、删除及原报告兼容。记录数据模式和实测限制。 |

真实环境需与 [RELEASE](../RELEASE.md) 的发布条件一起验收。部署方提供有效数据和模型凭证后，分别记录已准备及初次准备证券的时延、来源覆盖和费用。
