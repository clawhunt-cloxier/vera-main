# ADR-0004：盘中行情与研究数据截止时间

状态：草案，T026 实施中；本文记录 2026-11-13 用户确认的目标，不表示代码或契约已完成。合并前须同步修订 SPEC、DATA_SERVICE、HARNESS、受影响技能及评测、数据与 API 契约，并由独立工程审查。本文取代 ADR-0003 中排除盘中实时行情的范围，不改变不得输出投资建议等边界。

## 背景

用户要求研究时同时获取盘中实时行情与各数据集当时最新可用的数据，并确认允许数据存储、展示及第三方模型处理。数据集发布频率不同：实时行情、收盘日线、财报、持仓和公告不能共用一个“实时”标签。厂商账号某次调用成功不能证明所有产品、字段、时延及历史版本能力。

现有计划创建时固定 `as_of`，但厂商请求在确认计划之后发生：新采集的行情 `available_at` 会晚于计划时点，按当前点时约束必须排除。直接放宽约束会引入未来数据；把请求时间显示成数据时间也不正确。

## 决定

1. 计划确认明确授权“开始采集后冻结一次最新可用数据”；计划的预览时点不能承诺最终行情值。采集完成后、分析开始前以数据库持久化的截止时间冻结快照；该时间必须不早于所有纳入记录的事件、接收、归档与可用时间。不能证明来源时间或可用时间的必需数据不得进入快照。
2. 截止时间一经落库，重试、恢复和报告各版本引用同一截止时间与快照，不因 worker 重启重新取数或更新截止时间。需要更近数据时创建新任务；取消与并发写入仍遵守 epoch、版本及步骤台账。
3. 行情须同时记录厂商、证券、价格及明确货币/单位、行情事件时间、接收时间、归档引用和延迟性质。只有授权能力、时区、事件语义和新鲜度阈值均已配置并验证时才能称盘中实时；缺失、延迟、过期、停牌、断线、限流、无权限须明确标注或按章节规则受限/弃权，不能由历史收盘价冒充实时价。盘后行情必须标识交易日及收盘状态。
4. 非实时数据按自身发布周期、公告日及允许使用的历史版本选择最近可用值。缺乏可靠的 PIT 或公告版本关联时，不能声称历史时点正确或将后来修订的值冒充当时已披露数据；财务必需字段不满足时按技能规则弃权。
5. 每个报告显示快照截止时间和各数据集实际来源、事件/披露或期间、系统接收/可用时间、延迟与限制。汇总值的展示不得暗示所有来源在同一时点更新；每个数字仍须绑定证据或计算记录。
6. 生产路径禁止 fixture、伪造补值和隐式回退至模拟数据。测试环境可显式运行标记为模拟的 fixture；真实数据失败应返回可诊断的缺失/错误状态。厂商账户级限流跨进程生效，不能通过多 worker 绕过。

## 契约迁移与实现顺序

- 需要给计划和任务区分计划预览时间与冻结截止时间：现有 `ResearchPlan.as_of` 和 `Task.as_of` 为必填非空时间，不能悄悄改变原含义。下一步在 OpenAPI 中明确新字段、未冻结时的可空状态、版本及兼容方案；在数据模型中定义截止时间与快照原子绑定及已有任务处理。未完成迁移前不启用该能力。
- 登记独立盘中行情数据集及证据字段；日线、估值和财报保留各自口径与更新频率，不把盘中快照伪装成完整日线。契约、技能版本、测试样例及实现一起升级。
- 研究启动应基于已登记授权能力执行确定性取数、归档、映射、质量检查和冻结；模型不决定取数。尚无真实适配器或声明不完整时，明确不可用。

## 验收样例

模拟交易日盘中任务：计划与确认间隔超过行情新鲜度时，采集阶段重新取数，截止时间不早于事件与接收时间；过期、缺失、未授权与服务故障时不能展示旧值为实时。重试和重启沿用已冻结快照。财报报告期早于截止而公告晚于截止、或只能取得修订后值时，不能进入当时快照。盘后行情须标记收盘时点；无行情权限时明确受限或弃权。
