# Choice / EMQuant 接入手册

状态：开发中。已验证 Linux SDK 登录、历史序列、财务截面、交易日历、行情快照及独立 S3 归档；应用研究流程尚未接入真实厂商，不能据此声称已生成真实或实时研报。完成条件是必需数据集、来源血缘、快照、新鲜度、权限、故障处理及报告链路通过真实端到端验收。

## 运行依赖与凭证

- 项目采用 Go，Linux 原生绑定在 `backend/internal/dataservice/emquant`，通过 cgo 动态加载厂商库；不把 SDK 二进制、账号、密码、授权文件或登录日志提交仓库。账号密钥应由运行环境的 secret 机制传入，不放在命令行、日志、镜像或前端。
- 厂商库及同目录的服务器配置必须由部署方按授权独立提供，SDK 会写入运行目录，应使用可写的隔离副本。组件当前只提供库接口，生产配置、进程管理和应用注册尚未实现。
- `OpenRuntime` 将原生 SDK、S3 兼容归档和 PostgreSQL 共享限流器组合为一个采集单元；缺少限流状态表时登录不会执行。该单元没有注册到研究服务，不生成可直接用于报告的统一记录。账号、密码从部署密钥机制传入；不要打印配置或错误上下文中的敏感值。
- 官方 Linux C++ SDK 的 `EmQuantAPI.h` 可从[厂商下载中心](https://quantapi.eastmoney.com/Download?from=web)获取。2026-11-13 下载的 x86-64 动态库与用户提供的 Python 包内同架构动态库 SHA-256 一致；这不保证未来版本 ABI 一致。
- 用户已确认允许数据持久化、向用户展示及第三方模型处理；应用仍须登记具体数据产品和字段权限，再启用对应生产用途。迁移 `00012` 创建受控的 `source_licenses`，默认不生成任何许可；证据引用必须由管理侧依据实际产品权限维护，引用字符串本身不证明厂商授权。

厂商的[Python 手册](https://quantapi.eastmoney.com/Upload/EMQuantAPI_Python.html)和 [Linux C++ 手册](https://quantapi.eastmoney.com/Upload/EMQuantAPI_CPP_Linux.pdf)定义 API、参数和内存释放；字段口径以具体数据产品及版本为准。用户提供的终端口径应在正式数据产品登记中记录来源与确认人，不把上述概括当作完整合同原文。

使用非 fixture 数据提供方时，应用数据服务排除数据库遗留的模拟厂商记录和模拟实体，包括查询、覆盖检查、证据读取及旧快照回放；常规同步不能重新授予已撤销的模型处理权限。模拟实体与真实实体代码冲突、提供方 ID 对应的模拟性质冲突时同步报错，需要治理处理，不能静默合并。现有过滤依赖数据库中真实的提供方与实体标记，不能识别过去已被错误标记的数据。此隔离不代替真实厂商注册、字段许可与血缘持久化。

现有数据服务同步对不可变记录键进行冲突校验：相同键只有内容、来源和时点一致时才算幂等重放，否则整个同步事务失败，不会静默把另一来源或不同内容当作已保存。这是临时的拒绝路径，尚未实现 DATA_SERVICE 要求的多厂商冲突登记、对账与隔离，也未补齐原始血缘表。

## 归档、验证与剩余工作

SDK 只暴露解码后的类型化结果；组件将该结果按内容哈希写入 S3 兼容存储，关联请求指纹和字段位置。它不是厂商原始网络字节。迁移 `00011` 与 `ArchiveRegistry` 为经对象回读和哈希校验的 v2 归档登记请求指纹、来源和时间；`Runtime.RegisteredCollector` 对 CSD、CSS、交易日和行情快照在采集前及登记事务内分别核对产品、数据集、厂商方法、字段、证券或市场范围和存储用途的有效许可，登记成功后才返回采集结果。证券范围可明确登记为列出的代码或全部代码；全部代码需要相应授权依据，不能由单次成功请求推断。登记只建立可核验的原始层身份，不证明厂商来源或证据真实性、也不是研究可用时点；调用期间许可撤销或数据库失败时，已写入对象可能成为未登记对象，不能进入研究。单独调用 `ArchiveRegistry.RegisterCube` 产生的未绑定许可的记录仅供原始层准备，不能作为研究依据。应用尚未接线至该登记路径。原始对象与统一记录的关联、可见时间、快照冻结、权限撤销和旧写入保护仍需实现，不得丢弃 `MappedRecord` 的血缘后直接写入当前 `records` 表。

行情映射准备组件从归档校验单证券 `TIME,NOW` 请求、数据哈希、接收时间与字段位置，拒绝过期或不匹配的数据；单精度价格按其实际精度转成十进制字符串。映射参数必须提供时间和单位的依据引用、许可引用及新鲜度阈值；声明实时或延迟还需延迟依据引用。**引用字符串本身不是验证**：生产数据治理层必须解析并核验真实依据、权限和适用产品；在此之前不能将映射结果作为已验证实时行情或写入研究快照。当前厂商 `NOW/TIME` 及延迟口径仍未确认。

迁移 `00013` 增加受控行情映射政策和独立待发布层。`StageQuote` 重读已许可登记的单证券归档，在事务中重验当前许可、证券身份、映射政策和数据库时间，再生成不可变的候选行情及字段位置。无法证明交易状态时保留 `unknown`；未知延迟不得称为实时。`PublishStagedQuote` 在前一事务提交后重新验证归档、许可和新鲜度，在独立事务写不可变发布标记及数据库时钟；该标记不代表在其事务提交之前的 MVCC 视图中已可见。`SelectPublishedQuotes` 在调用方的固定数据库视图中挑选已提交且当前用途获准的新鲜行情，回读归档核对映射并明确返回缺失证券；明确要求交易中实时行情时未知状态或未知延迟不满足要求。`BeginQuoteBoundary` 和 `SelectPublishedQuotesAt` 支持在同一读写事务中复用一个截止时间与固定视图，边界不能跨事务复用。该选择结果本身不是任务快照，必须由后续任务链路与其他数据、任务 epoch 和截止时间原子绑定，并在展示或模型调用时重新验证当前权限。行情未写入 `records`，真实数据服务的旧查询路径也暂时排除盘中行情数据集，不能通过旧路径绕过发布检查。政策引用需由可信管理人员独立核实，示例和测试不代表 Choice 的实际字段定义或许可。

迁移 `00014` 提供独立的行情意图与候选组件表，默认没有任何意图。`FreezeQuoteComponent` 要求同一事务的固定视图、已消费且可执行的计划、可信 0.4 确认意图和匹配的任务 epoch/revision；它在对象读取后重新锁定并核验任务，避免读取期间的取消被旧写入覆盖。组件携带计划哈希、证券清单、截止时间和所选行情的内容哈希，但它本身不是完整任务快照。未绑定到完整清单的组件是不可用于研究的候选，重试可在新视图产生新的候选；清理机制尚未实现。当前没有 API 写入 0.4 意图，也没有代码将该组件与其他数据集及任务状态原子绑定，因此不能启用新版研究或宣称任务级快照已完成。

`ReauthorizeQuoteComponent` 可在固定事务中核验候选组件的内容哈希、任务归属、已冻结的行情版本和原始对象，并按当前展示或模型用途分别重新检查许可；它不返回行情数据，也不证明该组件已绑定完整任务快照。后续报告和模型路径必须先验证完整快照绑定，在实际使用时分别执行当前授权检查；不能使用本函数替代该绑定。

`OpenRuntime` 的归档回读会核对对象引用与内容寻址位置、对象哈希、请求指纹和接收时间；行情、交易日历、两项财务字段、单级行业及部分证券资料观察值可从对象存储回读后映射。交易日历仍须保留市场维度及实际数据库提交时间，财务字段仍不能推断公告版本和披露时刻，行业观察值也不证明有效期或历史修订。哈希只证明内容一致，不能证明厂商来源或授权，引用及归档完成时间仍须通过数据服务的持久化登记和许可规则核验。

代码及简称候选使用独立的表格归档格式，保留所有返回行和原始字段；回放要求查询参数、指纹、对象引用与哈希一致。简称查询只发送经过校验的单个明确简称，不发送自由形式的研究问题；也不会把有歧义的候选静默选择为研究对象。结果仍需经实体目录的市场、身份、版本与许可规则核验。

财务部分字段映射保留证券、**请求的**报告期和报表类型、两个金额值、空值及字段级归档位置；负利润和零值原样保留。报告期是请求参数，响应本身尚不能证明数值对应的公告版本、披露时间或 PIT 正确性，也不是完整财务报表，因此不能直接写入研究快照或作为完整财报使用。

已按官方头文件新增 CFN 公告／资讯元数据调用与归档准备，模拟动态库覆盖模式、上游错误、归档失败和请求指纹；当前尚未用真实账户验证该接口的权限、响应形状或字段映射。厂商返回的 URL 和文本是不可信数据，不得执行其中的指令，也不得以返回的 URL 绕过已登记数据源进行任意抓取。元数据不等于公告正文。

共享限流准备组件使用 PostgreSQL 会话锁和持久状态，将同一账号各类 SDK 调用串行化，调用结束后等待配置的最小间隔；必须直连 PostgreSQL 或使用保持会话亲和性的连接池，不能使用事务池化来承载会话锁。下限不快于 700 次/分钟，未知的账号或快照限额必须另行配置为更严格值，不能把该下限当作实际配额。收到已确认的厂商限频错误时，组件将另行配置的冷却时间持久化供所有进程遵守；它不自动重试，也不猜测实际账号所需冷却时间。限流状态写入失败、无法取得数据库连接、或发现上一次请求可能仍在执行时，均拒绝新请求；不能仅凭锁释放判断 SDK 调用已经结束。迁移 `00010` 创建 `emquant_rate_state`，由系统连接角色访问；工作区角色不能更新账户级限流状态，非空状态表不能直接回滚删除。采集器可以注入该限流器，但当前默认未注入，也未接入应用。必须确保同一厂商账号的所有进程及外部应用共享相同的非秘密 scope 且禁止绕过；否则不能宣称已实现账号级保护。未解决的 in-flight 状态必须先确认全部旧 SDK 进程已终止，并按已验证的账号冷却要求恢复；不能盲目清除。自动恢复机制、部署和真实账号限额仍未验证。

### 独立行情采集命令

`vera emquant quote --entity <entity-uuid> --code <证券代码> --license <license-uuid> --policy <policy-uuid>` 使用已登记的真实厂商、产品、证券和政策采集并发布一个行情候选；成功输出候选 ID 和数据库可用时间，不生成研究快照。发布过程中出错时若已产生候选会输出其 ID，不应将错误当作成功。执行 `vera emquant publish --candidate <候选-uuid>` 可重新验证来源及当前存储许可并恢复发布；该操作无需 SDK 登录或重新请求厂商，已提交的发布会保留原可用时间。数据库连接成功后的采集尝试写入成功或失败审计，不记录账号密码、对象存储密钥或返回值；参数、配置或数据库连接失败时无法写入数据库审计。

进程环境必须提供 `DATABASE_URL`、`EMQUANT_LIBRARY`（SDK 库绝对路径）、`EMQUANT_USER`、`EMQUANT_PASSWORD`、`EMQUANT_ACCOUNT_SCOPE`、`EMQUANT_S3_ENDPOINT`、`EMQUANT_S3_REGION`、`EMQUANT_S3_ACCESS_KEY`、`EMQUANT_S3_SECRET_KEY`、`EMQUANT_S3_BUCKET`、`EMQUANT_PROVIDER_ID`、`EMQUANT_PRODUCT`、`VERA_CONTRACTS_DIR`、`EMQUANT_MIN_INTERVAL` 和 `EMQUANT_RATE_COOLDOWN`；可选 `EMQUANT_S3_PREFIX`。限流间隔至少 90ms，冷却时间不得短于间隔；实际账号、方法和其他程序共享的限额仍须独立核验。数据库需预先迁移并由受控人员登记经核实的许可、证券及映射政策；不要把凭证放进命令参数或仓库。该命令不会替代当前缺失的 0.4 应用接线，也不能单凭调用成功证明实时权限或时效。

恢复发布只需上述数据库和 `EMQUANT_S3_*` 对象存储配置，无需 SDK 路径、Choice 账号密码或限流参数。连接数据库后的恢复尝试会写入成功或失败审计；权限撤销、来源损坏或尚未发布的候选过期等情况不会伪报成功。

迁移 `00016` 和 `FreezeLatestSnapshot` 为已确认的 0.4 任务提供固定 MVCC 视图内的原子清单绑定：受信确认流程预先保存不可变的数据集要求，行情组件和截止时间与任务 epoch/revision 一起写入；并发或重试读取已绑定清单。当前只有个股行情有已发布数据选择器，其他要求的数据集明确标记 `unavailable`，必需数据缺失时禁止通过该路径发送给模型。`ReadBoundSnapshotQuote` 在验证完整绑定和当前用途许可后读取原冻结行情；调用方必须在实际使用期间保持事务，后续用途须重新授权。这里尚未实现低频数据发布与选择、0.4 确认流程、任务 worker 或报告接线，不能将清单当作可交付研报。

`BoundQuoteFacts` 可把经绑定和模型用途授权的单股冻结行情转换为 Harness 事实，并保留原价格精度、行情时间和归档字段位置；尚未接入任务执行、证据 API 或报告。证据展示需要重新检查展示授权，不能把已授权模型用途当作展示许可。
