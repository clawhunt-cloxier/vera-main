# 发布阶段与外部依赖

## 1. 发布阶段

| 阶段 | 数据 | 模型 | 用户 | 进入条件 |
| --- | --- | --- | --- | --- |
| DEV | fixture 适配器（明确标注模拟） | 录制回放或真实模型 | 开发者 | 本地或开发机 |
| DEMO | 至少一家真实厂商，覆盖三项技能的必需数据集 | 真实模型（EXT-02） | 用户指定的少量内部人员 | V01、V03–V06 通过；EXT-01、EXT-02、EXT-03 就绪；页面显著标注“演示版” |
| PILOT | 同 DEMO | 同 DEMO | 邀请的一线投研人员 | V01–V09 通过；评测达到 TESTING §3 门槛 |

扩大注册和付费属于后续版本。合规适用性核查（EXT-05）在 PILOT 前完成；它不阻塞 DEV 和 DEMO，也不设置逐报告人工审批。

生产环境默认关闭注册与真实研究，以下三项都具备时才开启：配置完整、数据许可确认、模型价格表已配置。

## 3. 发布清单

SPEC V01–V09 的证据、TESTING 评测结果、镜像摘要与依赖锁、迁移兼容性、技能/规则/提示词/模型版本、备份恢复演练记录、告警、费用总上限开关、TLS 与 OIDC 回调地址。

首版目标 RPO 24 小时、RTO 4 小时，须经演练验证，不预先声称达标。部署形态为单机 Docker Compose，不承诺高可用。发布顺序：先执行兼容迁移，再部署 Worker，再部署 API 与 Web。失败时停止推广并回退到兼容的旧镜像，不自动执行破坏性的回退迁移。

## 4. 合规核查入口（PILOT 前）

以下是需要核查的现行规则入口，本文不构成法律结论：

- [生成式人工智能服务管理暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)
- 《人工智能生成合成内容标识办法》及强制性国家标准 GB 45438-2025（2025-09-01 施行）：报告页的显式标识，以及导出内容的隐式标识。首版已提供报告 PDF 导出（README-MVP §10），导出文件的显式与隐式标识是否满足上述要求尚未验证，须在上线前核查；显式标识见 SPEC §4。
- 证券投资咨询业务的边界：输出边界（ADR-0003 D2）是产品设计，不能据此宣称“不构成投资咨询”。是否需要资质，或是否需要与持牌机构合作，由 EXT-05 确定。

## 5. CI/CD

[Verify 工作流](../.github/workflows/ci.yml) 安装锁定的依赖，依次运行文档与契约检查、Go race 测试、TypeScript/Vite 构建、Go 格式检查与 vet。Action 固定到具体提交，权限仅为 contents:read，不配置生产凭证，不调用收费模型。

测试环境 CD 已实现（[deploy.yml](../.github/workflows/deploy.yml)，详见 [DEPLOYMENT](DEPLOYMENT.md)）：dev 分支 push 后等待同一 commit 的 Verify 成功，构建单镜像并推送 GHCR（标签 dev 与 sha-<12位>），经 SSH 更新测试服务器，以 /readyz 做健康检查，失败自动回滚到上一个健康镜像。SBOM、镜像摘要记录与生产推广仍属 T023。

T023 增加版本发布：用通过 CI 的 commit 构建 api、worker、web 镜像并推送 GHCR，记录镜像摘要、SBOM、迁移版本和技能版本；生产环境推广同一摘要，不重新构建。

## 6. 发布分支

遵循 [分支规范](BRANCHING.md)：任务先合入 dev；候选版本回归通过后，经发布 PR 以普通 merge commit 合入 main。上线绑定已验证的 commit 与镜像摘要，main 合并不会自动部署。
