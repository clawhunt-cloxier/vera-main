# 试用发布与外部依赖

## 发布阶段

DEV：模拟隔离环境，可开发/演示；PILOT：真实数据网站供邀请的基金经理和散户试用；扩大注册/付费属于后续版本。合规适用性在开发后期处理，不阻塞DEV，也不设置逐报告人员审批。

## 不能由Agent虚构的条件

| ID | 外部条件 | 代码可先完成什么 |
| --- | --- | --- |
| EXT-01 | 数据产品、真实API文档、凭证与向两类用户展示/模型处理许可 | Provider接口、模拟适配、映射/授权/对账测试 |
| EXT-02 | 模型端点、实际model_id、密钥、价格表与地区/处理条款 | 通用兼容适配、受控mock、预算与结构化校验 |
| EXT-03 | 域名、TLS、部署主机、对象存储、备份位置与OIDC/邮件配置 | Compose、部署手册、readiness和恢复脚本 |
| EXT-04 | 真实授权验收语料与独立金标准 | fixture/对抗集框架、评测执行器 |
| EXT-05 | 开发后期确认对外服务地区、数据/隐私条款和业务适用性 | AI标识、留证、权限、删除与可配置规则 |

生产启动默认关闭真实注册和研究，只有配置充分且PILOT验收完成后启用；缺模型价格/数据许可时不发送真实请求。邀请制不是法律适用豁免。部署开关不是逐任务人工审核。

## 发布清单

SPEC V01–V09、TESTING结果、镜像摘要/依赖锁、迁移兼容、worker重放、模型/规则/模板版本、备份恢复记录、错误告警、预算开关、TLS与OIDC回调准确。生产数据恢复目标RPO24小时/RTO4小时作为首版目标，必须演练，不先声称达标。

首版单区域Docker Compose/现有容器平台，业务库与对象存储持久卷/托管依赖；单机应用不承诺高可用。先部署兼容迁移和Worker，再更新API/Web；失败停止推广并回到兼容旧镜像，不自动破坏性down migration。

## CI/CD 的实施边界

当前 [Verify 工作流](../.github/workflows/ci.yml) 在 main 推送、PR 和手动触发时运行：安装锁定依赖 → 文档与契约检查 → Go race 测试 → TypeScript/Vite 构建 → Go 格式与 vet。Action 固定提交，默认仅 contents:read；不配置生产凭证，不运行收费模型。该流程验证工程起点，不代表业务验收或已部署。

T009 增加版本标签发布：以通过 CI 的不可变 commit 构建 API/Worker/Web 镜像，推送 GHCR，记录镜像摘要、SBOM、迁移与工作流版本。发布环境使用独立凭证和部署锁；推广同一摘要，不在生产重新构建。依次执行备份检查、兼容迁移、Worker、API/Web、readiness 与冒烟；失败停止推广并回滚兼容应用版本。数据库删除列与旧 Worker 退役另行分阶段执行。使用 GitHub 环境受控发布，具体操作者权限在部署任务中配置；这不是研究业务审批。

后续多实例部署先扩展无状态 API 与 Worker，并把限额、租约和公平调度保留在共享数据库/Temporal。API 不依赖本机 session；对象存储不依赖容器磁盘。达到实测容量瓶颈再迁移托管数据库/Temporal、缓存或 Kubernetes，沿用相同逻辑契约，避免首版同时承担基础平台建设。

## 发布分支

遵循 [分支规范](BRANCHING.md)：任务先合入 dev，候选版本通过回归后经发布 PR 合入 main，使用普通 merge commit。上线绑定已验证的 commit 与镜像摘要；main 合并不自动部署。修复和发布记录同步回 dev。
