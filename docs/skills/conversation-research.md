# 工作台对话研究

日成交使用 `stock_analysis`，融资余额使用 `capital_flow`。收盘数据版本为 `1.2.0-chat-close.2`，已交付的 `1.2.0-chat-close.1` 仍可查阅。模拟环境为 `1.2.0-chat-fixture.1`。单 Choice 使用 `1.2.0-chat-choice.1`，沿用 [日成交观察简报](stock-observation-brief.md) 的归档和核验。

股价横向对比登记为 `stock_analysis` 的独立技能版本。TuShare 收盘版为 `1.3.0-chat-compare-close.3`，模拟版为 `1.3.0-chat-compare-fixture.2`。旧结果保留原技能版本与证据读取，未保留样本哈希的早期预览对话在下一轮重新选取同行。

| 主题 | 交易日窗口 | 冻结输入 | 展示 |
| --- | --- | --- | --- |
| 日成交 | 1、5、10、20、60 | `ref.trading_calendar` 与 `mkt.daily_bar`。仅使用已结束交易日可用记录。 | 最近有效日的成交量和成交额，柱状图与明细。单位为手和万元。 |
| 融资余额 | 5、20、60、120 | `ref.trading_calendar` 与 `flow.margin`。需要两个有效观测。 | 最近披露余额、首末有效日差额、余额图和明细。差额使用 `F18.balance_change`。 |
| 单 Choice 日成交 | 最近最多 20 个日期 | Choice 已冻结的日成交观察。 | 保留厂商返回的日期。柱状图和明细均以万元展示成交额，并引用同一条归档证据。 |
| 股价横向对比 | 5、10、20、60 | `ref.trading_calendar`、带复权因子的 `mkt.daily_bar`。自动同行样本另冻结 `ref.industry_peer_sample`，绑定当时用于排序的行业名录和市值响应。可选指数使用 `mkt.index_bar`，按样本或基准股票的 `ref.industry` 确认行业。 | 同图展示归一化的股票及指数走势、区间起止收盘价或指数点位、涨跌幅、相对基准的百分点差和有效日数。 |

默认窗口为 20 个交易日。冻结结果直接引用 Harness 报告版本。缺失日期留空，覆盖不足时展示实际范围与缺失原因。日成交及融资余额短技能最多写作三条已核验结论。横向对比为每个纳入比较的对象给出一条由计算生成的结论。所有短技能沿用禁用表达检测与证据权限。从任务创建到报告交付最多 90 秒，最多四次模型调用。费用及 token 上限沿用对应技能预算。

用户提供明确对象和范围后，服务保存计划并自动执行。改窗口、指标或对象会自动开始新的一轮。追问来源、结果与公式复用同一会话中的原交付。完整研报使用正式技能的章节、核验和交付，工作台也提供独立的完整研报入口。

## 对话工具契约 v15

| Tool Call | 用途 |
| --- | --- |
| `inspect_daily_trading` | 查看个股已公布的日成交额和成交量。 |
| `inspect_financing_balance` | 查看个股已披露的融资余额及区间变化。 |
| `compare_stock_performance` | 比较 2 至 5 只点名 A 股，或比较基准股与至多 3 家申万二级同行。可加入行业和宽基指数，也可查看一只股票与指数的走势。 |
| `analyze_stock` | 生成完整的个股财务、估值指标、行情与风险分析。 |
| `analyze_capital_flow` | 生成完整的资金动向报告。 |
| `run_deep_research` | 生成公司或行业的深度报告，具体范围随部署登记的技能而定。 |
| `reference_research` | 查看已交付结果、原始证据或确定性计算。 |
| `lookup_finance_knowledge` | 为通用金融概念、机制及相关追问查证公开资料，提供简短解释与网页来源。 |
| `respond_to_user` | 生成针对本轮问题的金融解释、问候、澄清或范围提示。 |

网关按部署登记短研究和完整研报工具，声明支持的对象类型、交易日窗口和默认值。只接入 Choice 的环境开放日成交短研究，使用最近最多二十个有效日期。正式技能沿用各自的窗口和章节目次。每轮允许一个工具调用，工作台展示核验后的研究结果。股价横向对比请求使用 `conversation-comparison-tool`。

每轮由模型选择具体指标或报告工具。只改标的或窗口时可再次调用同一个工具。查过日成交后问「融资余额呢」，模型调用 `inspect_financing_balance`，让服务沿用同一个标的。省略窗口时，同一主题或同标的的短研究沿用上一轮在该工具支持范围内的天数，否则采用当前工具默认窗口。追问优先使用用户点选的交付轮次，其次使用紧邻的澄清范围，再使用前次研究范围。

模型从当前消息摘取标的名称或代码。Go 使用登记别名匹配标的，校验窗口与技能。如果调用参数遗漏同类型的明确标的，或选定窗口与消息中的交易日数不符，服务会要求澄清。未支持的自然日和日期区间也需要澄清。

用户在澄清轮只补充股票代码，或说「同样的口径，换成另一只」时，沿用已核验的指标和支持的窗口。模型填入 0 或相同的已核验窗口均可，明确指定的新窗口仍须与本轮消息一致。

日成交与融资余额由数据治理层检查本次窗口内已发布的规范记录。日成交补齐缺失日线记录所需的收盘、停复牌和复权输入，融资余额只补 `margin_detail`。短研究与其他技能共享记录，快照只冻结本轮需要的行情或融资数据及日历。

对原结果的自然语言追问可以引用同会话有权读取的最近六轮已交付范围。模型根据标的、指标、窗口和历史顺序选择 `result_turn`，后端核对对应轮次及用户明示的标的和范围。点选结果优先，也可以用于引用更早的轮次。引用复用原始快照和计算。

### 股价对比口径

- 点名比较时以第一只股票为基准。用户只点名新的对比对象并指代上文时，以会话标的为基准。
- 对某只股票追问「和同行比呢」时，Go 按样本日有效的申万二级行业成员与同期总市值选择同行。先按与基准总市值之差的绝对值排序，相同差距按证券代码排序，取至多三只。结果显示样本日和行业类别。
- 默认只画股票。用户说「加上行业指数」时，按基准股的申万二级归属取对应收盘指数，已选同行时取样本所用行业。宽基可选择沪深300（`000300.SH`）、中证500（`000905.SH`）和中证1000（`000852.SH`）。泛指「大盘」或「加个宽基」时使用沪深300。
- 在已有标的或对比范围时，「同行呢」「大盘也看看」沿用上下文。理解「拉长一点」「缩短一点」时在 5、10、20、60 个交易日中移至相邻窗口。「就按这十天」可以指代上一轮已选定的 10 个交易日。有明确的新交易日数时使用用户给出的数值。
- 对齐最近已结束交易日。对象和共同日期均须达到窗口的 80%，至少有两个有效日，末日须在最近两个已结束交易日内。先计算股票共同日期，再依次纳入行业指数和已选宽基。无法满足要求的指数留在明细说明原因，其余曲线保留。
- 股票使用复权收盘价，指数使用收盘点位。图表将各曲线首个共同有效日设为 100，区间涨跌幅共用起止日。Harness 通过 `F12.period_return` 计算涨跌幅。明细中的百分点差由 `F13.excess_return` 计算，为该行涨跌幅减去基准股票同期涨跌幅，点击相应结论可核对公式和输入。
- 「同一组改成 60 个交易日」保留基准、同行、行业样本及所选指数。数据治理层按证券和交易日复用已发布的合格行情，只有缺失的日线、复权因子或指数点位需要请求厂商。用户可通过「不看沪深300了」「加上中证500」等追问分别调整指数，或说「只看股票」移除全部指数。首次对比的窗口需要澄清时，可直接回复支持的交易日数。

问候、身份、致谢和一般金融问题由同一模型理解并作答。`respond_to_user` 的参数及兼容的直接 JSON 回复使用 `conversation-answer-output` 的 `kind` 与 `message`。模型根据本轮问题和最近的金融问答解释概念、交易机制和口径。回复提示说明金融教育和投资建议的差异，并让模型对不宜展开的话题回复「换个话题聊聊吧」。Go 检查文本格式和长度。语义核验使用 `conversation-review-output` 核对草稿、问题和当前部署支持的范围，决定保留或丢弃草稿。教育语境可使用正常金融术语和符号。每次工作执行可重写一次，原草稿不会交给重写模型或写入对话。模型未配置时显示服务状态。专用内容分类器留待后续接入既有审核流程。

启用联网查证时，模型通过 `lookup_finance_knowledge` 选择登记的公开主题和侧重点。比如，用户问过零息债券后追问「那现金流是什么样的？」，模型选择 `zero_coupon_bond` 和 `cash_flows`。Go 验证两个标识并用登记的文字生成公开问题。取回的公开资料交给另一次普通模型调用，结合原问题和上下文作答。核验通过的回复展示此轮实际检索且引用的 HTTPS 来源。找不到相关主题或可用来源时，可以交付经核验的通用解释，并提示本轮没有可引用的网页来源。

证券事实、行情和计算使用已登记的研究工具。混合请求可交付历史研究，并显示本轮交付范围。一次工作执行的模型总时限为 20 秒，搜索最多尝试一次。重投继续使用同一轮的剩余调用次数。模型调用台账仅记录费用核对所需的元数据。

新会话先保存「新会话」。单独的 River 作业用同一个 `router` 根据首条消息生成 `conversation-title-output`，检查标题格式、长度和语义。旧首句截断标题由后台分批补生成。作业领取时先保存「新会话」，生成失败或领取后中断时继续使用这个标题。重新打开历史时可看到生成后的摘要。标题写入和会话修订号、历史排序独立。对话入口不设每分钟发言次数或每日研究次数。每会话同一时间处理一轮，运维保护继续约束模型调用和后台作业。

v6 在引用已交付内容时以已绑定的报告为准。服务核对用户明确写出的标的和窗口，忽略仅由模型添加的标的名称。模型摘取的代码缺少市场后缀时，请用户补充或改问原报告。v5 的路由示例区分追问原公式、解释通用概念和沿用标的改窗口。报告技能版本见本页开头。评测见 [对话问题样例](../../tests/fixtures/conversation-cases.json)。
