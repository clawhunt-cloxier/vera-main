# 工作台对话研究

日成交使用 `stock_analysis`，融资余额使用 `capital_flow`。收盘数据版本为 `1.2.0-chat-close.1`，模拟环境为 `1.2.0-chat-fixture.1`。单 Choice 使用 `1.2.0-chat-choice.1`，沿用 [日成交观察简报](stock-observation-brief.md) 的归档和核验。

| 主题 | 交易日窗口 | 冻结输入 | 展示 |
| --- | --- | --- | --- |
| 日成交 | 1、5、10、20、60 | `ref.trading_calendar` 与 `mkt.daily_bar`。仅使用已结束交易日可用记录。 | 最近有效日的成交量和成交额，柱状图与明细。单位为手和万元。 |
| 融资余额 | 5、20、60、120 | `ref.trading_calendar` 与 `flow.margin`。需要两个有效观测。 | 最近披露余额、首末有效日差额、余额图和明细。差额使用 `F18.balance_change`。 |
| 单 Choice 日成交 | 最近最多 20 个日期 | Choice 已冻结的日成交观察。 | 保留厂商返回的日期。柱状图和明细均以万元展示成交额，并引用同一条归档证据。 |

默认窗口为 20 个交易日。冻结结果直接引用 Harness 报告版本。缺失日期留空，覆盖不足时展示实际范围与缺失原因。短技能最多写作三条已核验结论，沿用禁用表达检测与证据权限。从任务创建到报告交付最多 90 秒，最多四次模型调用。费用及 token 上限沿用对应技能预算。

用户提供明确对象和范围后，服务保存计划并自动执行。改窗口、指标或对象会自动开始新的一轮。追问来源、结果与公式复用同一会话中的原交付。完整研报使用正式技能的章节、核验和交付，工作台也提供独立的完整研报入口。

## 对话工具契约 v6

| Tool Call | 用途 |
| --- | --- |
| `inspect_daily_trading` | 查看个股已公布的日成交额和成交量。 |
| `inspect_financing_balance` | 查看个股已披露的融资余额及区间变化。 |
| `analyze_stock` | 生成完整的个股财务、估值指标、行情与风险分析。 |
| `analyze_capital_flow` | 生成完整的资金动向报告。 |
| `run_deep_research` | 生成公司或行业的深度报告，具体范围随部署登记的技能而定。 |
| `refine_research` | 保留主题，改变交易日窗口或补充、替换标的。 |
| `reference_research` | 查看已交付结果、原始证据或确定性计算。 |
| `respond_to_user` | 选择服务端提供的金融解释、问候、澄清或范围提示，不创建研究。 |

网关按部署登记短研究和完整研报工具，声明支持的对象类型、交易日窗口和默认值。只接入 Choice 的环境开放日成交短研究，使用最近最多二十个有效日期。正式技能沿用各自的窗口和章节目次。每轮允许一个工具调用，工作台展示核验后的研究结果。请求使用 `conversation-window-tool`、`conversation-depth-tool` 或 `conversation-reference-tool`。

模型从当前消息摘取原有标的名称或代码。Go 使用登记别名匹配标的，校验窗口与技能。如果调用参数遗漏同类型的明确标的，或选定窗口与消息中的交易日数不符，服务会要求澄清。未支持的自然日和日期区间也需要澄清。追问优先使用用户点选的交付轮次，其次使用紧邻的澄清范围，再使用前次研究范围。

问候、身份、致谢和金融概念由模型理解。`respond_to_user` 的参数及兼容的直接 JSON 回复均使用 `conversation-answer-output`。该结构只允许回复类别和概念选项。服务根据当前能力和已审定的概念说明生成回复。金融知识目前覆盖估值指标、财务报表、交易、资金口径、风险与常见金融产品。对于没有可用数据或工具的问题，说明当前能力。用户在同一条消息中提出可独立核验的历史研究和投资建议时，运行历史部分，并同时显示服务边界。

v6 在引用已交付内容时以已绑定的报告为准。服务核对用户明确写出的标的和窗口，忽略仅由模型添加的标的名称。模型摘取的代码缺少市场后缀时，请用户补充或改问原报告。v5 的路由示例区分追问原公式、解释通用概念和沿用标的改窗口。报告技能版本见本页开头。评测见 [对话问题样例](../../tests/fixtures/conversation-cases.json)。
