## 实际执行检查与结果

### 1. 实时与低频数据分离

**通过。** `mkt.intraday_quote`（个股）和 `mkt.intraday_index_quote`（指数）作为独立数据集登记，grain 含 `event_at` 和 `provider_id`，均独立于 `mkt.daily_bar` 与 `mkt.index_bar`。两个数据集均有 `event_at`（行情事件时间）、`received_at`（系统接收时间）和 `latency_mode` 字段。ADR §3 和技能文档 S2、S6 均要求各来源时间分别展示，不得合并为同一"实时"标签。

### 2. 快照冻结语义正确性

**通过。** ADR §1 要求"采集完成后、分析开始前以数据库持久化的截止时间冻结快照；该时间必须不早于所有纳入记录的事件、接收、归档与可用时间"。ADR §2 明确"截止时间一经落库，重试、恢复和报告各版本引用同一截止时间与快照，不因 worker 重启重新取数"。评测样例 RT-06 覆盖"冻结后重启复用快照"场景。

API 草案中 `Task.snapshot_as_of` 类型为 `["string", "null"]` 且在 required 中，冻结前为 null，冻结后为不可变时间戳。`Report` 的 `allOf` 条件约束要求 `collect_latest` 模式必须有非空 `snapshot_as_of` 和 `source_freshness`。

**小问题（非阻塞）：** `Task` schema 没有 if/then 约束要求 `collect_latest` 任务在完成状态下 `snapshot_as_of` 必须非空。这个保证需靠实现层/DB 约束来保证，Draft 阶段可接受，实施 PR 须覆盖。

### 3. 未授权/延迟未知/过期/缺失时不标为实时

**通过。** `SourceFreshness.latency_mode` 是必填 enum：`real_time | delayed | unknown`。草案 schema 通过 `allOf` if/then 约束：`latency_mode: real_time` 时 `event_at`/`received_at`/`available_at` 必须为非空 date-time 字符串（`check_contracts.py` 有对应断言验证）。评测样例覆盖：RT-02（行情过期）、RT-03（收到时间晚于截止）、RT-04（延迟未知不标实时）、RT-07（收盘非实时）、RT-08（无权限弃权）。ADR §章节结果矩阵明确这些场景的弃权规则。

### 4. 财报历史时点正确性

**通过。** ADR §4 明确"缺乏可靠的 PIT 或公告版本关联时，不能声称历史时点正确或将后来修订的值冒充当时已披露数据"。评测样例 RT-05（报告期前截止但公告在截止后）和 RT-10（历史修订未知时不能声称 PIT 正确）直接对应。
