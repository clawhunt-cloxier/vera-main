# 数据接入选择与 T027 差距

基线：`origin/dev` `0052ea8`。建议继续使用数据治理层，按任务按需采集并冻结，Harness 读取有版本、时间及证据的快照。MCP 是接口传输协议，不能替代质量检查、持久化与研究时点管理；若未来某厂商只提供 MCP，应在数据服务中封装适配器，仍通过同一发布和冻结流程。

| 环节 | 基线实际实现 | T027 接线目标 |
| --- | --- | --- |
| 用户意图 | 网站默认 observation.v1；非实时日成交简报 | 0.4 明确选择实时成交或最近可用行情；选择写入计划哈希 |
| 计划确认 | `collect_latest` 仅支持 demo.2 | 确认事务登记 quote intent，与任务和 River 入队原子提交 |
| 厂商采集 | Choice 原生 SDK、账户限流、S3 原始归档已有 | worker 按确认意图调用 `CollectTaskQuotes`，不由模型决定取数 |
| 记录发布 | 映射策略、原始对象、staged quote 和 publication 已有 | 沿用现有发布协议，不把采集时间冒充数据库可用时间 |
| 冻结 | `FreezeLatestSnapshot` 底层已有；HTTP/worker 未使用 | 固定视图选取记录版本，原子绑定 cutoff、manifest 和 task epoch/revision |
| 模型使用 | `BoundQuoteFacts` 已有，未接任务执行 | 模型只接收确定性事实；每次发送重新验证当前用途，重试沿用原快照 |
| 报告与证据 | 非实时 observation 来源与日期 | 0.4 返回快照截止、事件/接收/可用时点、延迟与限制；报告、证据、PDF/series 均核验绑定 |
| 兼容 | 0.4 被拒绝 | 显式媒体协商；保留 0.3/observation，版本混用拒绝，旧 JSON 不泄露新增必需语义 |

因此，这不是“定时把所有 SDK 数据倒进数据库”和“让 Harness 通过 MCP 现查现用”的二选一。推荐的是任务驱动的受控采集：需要更新时请求厂商，确认归档与发布后冻结，用可重放快照支持后续事实表、模型和交付。数据库保存版本和可用时间，对象存储保存原始响应；读取一次厂商响应后直接交给模型无法提供同样的重试和审计保证。

边界仍然存在：单股行情简报不等于三项完整研究技能；财报披露版本、行业/市场覆盖与真实盘中验证仍需独立完成。基线 `d521f56` 已移除 observation 简报的 source_licenses 门禁和证券白名单，旧交接描述与当前代码存在差异；T027 不把这种账户凭证层面的可访问性当成实时性或用途证明，新的行情路径明确绑定 source license 与 mapping policy。真实登记内容不写入仓库，开发不会编造 TIME、状态或延迟证明。
