## 3. 产品阶段与专项步骤映射

产品阶段的业务范围和退出要求以 [产品规格 §13](financial-research-agent-development-spec.md) 为准。下表是唯一跨专项映射；旧步骤编号保留，方便已有任务引用，不表示必须按编号串行完成。

| 产品阶段 | 后端 | Agent | 数据治理 | 完成边界 |
| --- | --- | --- | --- | --- |
| P0 开发与集成 | P0-A → P0-B → P0-C | A1、A2；A4 的预算/成本台账基础；A5 的基础观测与故障测试 | DQ0、DQ1、DQ2 的去重/检索/反证基础 | 单研究路径贯通治理、验证和交付；可使用明确标记的模拟适配开发 |
| P0 真实上线 | 完整 P0 的权限、恢复、部署与容量验收 | A5 的目标容量、版本与故障验证 | 对实际来源完成 DQ4；DQ2 的缓存仅在启用时验收 | 真实许可和映射、预算、隔离、留证、恢复与目标负载验证通过 |
| P1 质量与成本优化 | 多角色、验证与评测模块扩展 | A3；A4 的路由/缓存/Jev 实验；A5 持续回归 | DQ3；按压测启用 DQ2 缓存 | 与单 Agent 和独立多样本比较，质量及成本收益达到预定条件 |
| P2 扩展与扩容 | 按负载拆分与存储扩展 | A5 的规模化优化及持续评测 | 新来源重复 DQ4，按规模优化 DQ2 | 对新增场景重新验证质量、授权、容量及恢复 |

D0–D3 是部署形态，独立于产品阶段：P0 可以在已有高可用平台运行，P2 也不必引入跨区域部署。D0 仅用于开发与集成；D1 及以后按后端 §15 的条件选择。

### Agent 步骤

| 阶段 | 交付 | 主要验收 |
| --- | --- | --- |
| A1 | ContextBuilder、T0 工具、Go RoleRunner、Operation 台账 | 单 Agent 取证与验证；双语言数值契约 |

| A5 | 并发压测、版本灰度、生产观测与持续评测 | 目标容量下延迟、错误率与资源满足定义的 SLO |

### 治理步骤

| 阶段 | 范围 | 退出条件 |
| --- | --- | --- |
| DQ0 契约与样例 | 空厂商注册、两套模拟字段、Canonical schema、指标字典 | Go/Python 契约、单位/时间测试通过 |
| DQ1 规则治理 | 原始快照、标准化、质量规则、分级、任务数据集 | 可追溯、冲突可见、Agent 读冻结版本 |
| DQ2 筛选与性能 | 去重、结构化检索、相关性、反证保留、Redis 适配 | 对照测试与缓存故障恢复通过 |
| DQ3 语义增强 | 观点/事实分类、重排、选择性 LLM/Jev | 增量收益优于成本且误删可控 |
| DQ4 真实来源上线 | 厂商许可、真实映射、配额、回补与 schema 漂移 | 真实金标准、压力测试与来源准入验收 |

Redis 接口可在 DQ1 预留，是否启用由 DQ2 压测决定。A4 的成本记账与预算限制必须在 P0 具备，后续才评估高级路由和供应商缓存；DQ4 对首批真实来源的验收必须在首次真实上线前完成。AI 分类不作为标准字段治理的前置依赖。
